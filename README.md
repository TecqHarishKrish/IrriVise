# IrriVise

IrriVise is a local irrigation research application. This repository currently contains a **working offline prototype**, not the complete research platform described in [the build specification](IRRIVISE_CODEX_MASTER_PROMPT.md). It uses seeded synthetic weather, a simple daily water-balance model, a hidden simulated reference state, an estimated twin, and a prototype CARAT observation decision. AquaCrop-OSPy evaluates completed schedules. A CPU quick PPO path trains and saves real checkpoints, but no research-grade model results or real farm measurements are available.

## Requirements

- Python 3.12 recommended (the tested bundled runtime was 3.12.14). On this Intel Mac, the compatible pins use PyTorch 2.2.2, Stable-Baselines3 2.3.2, Gymnasium 0.29.1, NumPy 1.26.4, and AquaCrop 3.1.0.
- Node.js 20 or newer with npm, or pnpm 11
- No paid API or cloud service

## Accounts and access control

IrriVise uses Supabase Auth for email-confirmed sign-up and sign-in. Copy `.env.example` to `.env`, copy `apps/web/.env.example` to `apps/web/.env`, and enter the URL and anon key from your Supabase project. Enable email confirmation in Supabase before inviting users. The verified account matching `IRRIVISE_PRIMARY_ADMIN_EMAIL` becomes the primary administrator. The API owns project data by account and checks each user feature permission server-side.

## Start locally (macOS/Linux)

```bash
./scripts/setup.sh
./scripts/dev.sh
```

After startup, the expected local addresses are `http://127.0.0.1:5173` for the UI and `http://127.0.0.1:8000/docs` for API documentation. The API, worker, and web process run separately and are stopped together when `dev.sh` exits. If a port is occupied, the corresponding process fails visibly; close the conflicting service before retrying.

For this Codex environment, Node and Python were available only through its bundled workspace runtime. Add the bundled Node `bin` and fallback `pnpm` directories to `PATH` before running the scripts. These paths vary by installation.

## Offline walkthrough

1. Open **Projects & Fields**, create a maize project and season scenario.
2. Open **Irrigation Simulator**, choose fixed, threshold, or prototype CARAT, then queue a run.
3. The separate worker processes the job, evaluates its precomputed irrigation schedule in AquaCrop, and stores its daily trace in `artifacts/runs/`.
4. Inspect **Digital Twin Studio**. The hidden reference is visible only under the post-run evaluation disclosure.
5. Open **Model Training Lab** for a real quick PPO smoke job. It persists a checkpoint only after save/load/inference verification.
6. Inspect CARAT traces, saved analytics, and download the latest run JSON from **Report & Export Center**.

All values in the offline dataset are generated by [`scripts/sample_data.py`](scripts/sample_data.py) using seed 42. They are **synthetic demonstration data**. The "yield proxy" is an uncalibrated score in t/ha scale generated by the simple simulator. It is neither measured yield nor AquaCrop-simulated yield. The AquaCrop adapter evaluates a precomputed schedule and reports **AquaCrop-simulated dry yield** under a distinct field name. The PPO quick preset uses repeated synthetic seasons and is a software smoke test, not evidence of policy quality.

## Tests

```bash
PYTHONPATH=packages/irrivise_core:services/api .venv/bin/python -m pytest tests -q
cd apps/web && npm run typecheck && npm run build
```

`./scripts/smoke_test.sh` runs both checks on a standard Node/npm installation. The API test creates a project, scenario and run, processes one queue item with the worker function, and reconciles saved totals with the daily trace.

Quick real training from the terminal:

```bash
.venv/bin/python scripts/train_ppo.py --preset cpu_quick --dataset sample --seed 42 --timesteps 2048
```

## Architecture and limits

See [ARCHITECTURE.md](ARCHITECTURE.md), [METHODOLOGY.md](METHODOLOGY.md), [REPRODUCIBILITY.md](REPRODUCIBILITY.md), and [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md). NASA POWER ingestion, historical splits, matched benchmarking, uploads, SQLAlchemy/Alembic and SSE remain pending. The PPO checkpoint has not been evaluated on held-out seasons, and CARAT has not been connected to it. Do not use prototype recommendations for field irrigation.
